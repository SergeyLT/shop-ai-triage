# Проверка качества обработки обращений

В папке находится воспроизводимый набор из 20 синтетических обращений интернет-магазина. В `cases.json` для каждого примера заранее заданы ожидаемые категория, необходимость участия оператора и смысловая проверка черновика. `report.md` содержит результаты живого прогона и ручной чек. Полные ответы модели сохранены в `snapshots/`.

## Как оценивать

- **Категория:** точное совпадение с `expected_category`.
- **Эскалация:** точное совпадение с `expected_escalate`; пропуск обязательной эскалации считается особенно серьёзным.
- **Фактическая точность:** ответ не утверждает неизвестные статус, сроки, наличие, правила, функции сайта, выполненный возврат или передачу оператору.
- **Черновик:** вежливый и полезный следующий шаг, без запроса пароля и полных данных карты; условие `draft_check` выполняется по смыслу, а не по совпадению слов.

Первые два пункта проверяются скриптом, последние два требуют чтения каждого ответа человеком. HTTP 200 с аварийным шаблоном помечается как `FALLBACK`, а не как результат модели. Разные формулировки одного смысла допустимы.

## Запуск

Нужны Python 3.12, локальный сервис по инструкциям корневого README и ключ приложения в `.env` или переменной `TRIAGE_API_KEY`. Из корня репозитория:

```powershell
python evals/run.py --live
python evals/run.py --live --ids C01 C04 --output output/evals/complaints.json
```

Для Linux команды те же, если `python` указывает на Python 3.12; при использовании виртуального окружения замените его на `.venv/bin/python`. Скрипт обращается к `GET /health`, затем последовательно вызывает действующий `POST /triage`. Флаг `--live` обязателен: каждый пример может расходовать оплачиваемые токены ProxyAPI. Результат по умолчанию сохраняется в игнорируемый Git файл `output/evals/latest.json`. Ключ в результат не записывается. Частичный прогон выбирается через `--ids`; состояние минутных и суточных лимитов сервиса сохраняется между прогонами.

После запуска сравните поля `auto` и заполните ручные проверки по условиям `draft_check`. При изменении модели, промпта или политики эскалации сделайте новый снимок и укажите версию условий. Прогоны с платной моделью не входят в pytest и CI.

Скрипт возвращает ненулевой код, если хотя бы одна автоматическая проверка не прошла, но сохраняет все полученные ответы для анализа.

Набор мал и составлен вручную. Он показывает конкретные успешные и проблемные случаи, но не оценивает статистическую точность на реальных обращениях. Для более надёжной оценки нужны анонимизированные реальные данные, повторные прогоны и независимая разметка.
