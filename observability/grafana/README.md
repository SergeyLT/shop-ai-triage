# Дашборд логов Shop Triage

Файл [shop-triage-logs.json](shop-triage-logs.json) предназначен для импорта в Grafana с источником данных Loki. Он показывает последние вызовы `/triage`, все события выбранного запроса, итог обработки, HTTP-результат и ошибки с безопасным ответом.

## Импорт

1. В Grafana откройте **Dashboards → New → Import** и загрузите `shop-triage-logs.json`.
2. Выберите существующий источник данных **Loki** для поля `Loki` и завершите импорт.
3. Установите интервал времени, который включает проверяемый запрос. В дашборде по умолчанию выбраны последние шесть часов и UTC.

Запросы рассчитаны на метку потока Loki `compose_service`, которую обычно передаёт сборщик логов Docker Compose. Если в вашей конфигурации Alloy метка называется иначе, замените селектор `{compose_service=~".+"}` в запросах панелей на селектор с существующей меткой. Остальные фильтры работают по полям JSON-лога, а не по меткам Loki; `request_id` не нужно добавлять в метки.

## Показ одного запроса

1. Отправьте `POST /triage` с обезличенным примером и скопируйте значение заголовка ответа `X-Request-ID`.
2. Вставьте это значение без кавычек в поле **Request ID** вверху дашборда и нажмите Enter.
3. В панели **Все события выбранного запроса** раскройте JSON-записи `triage_completed` и `request_completed`. В соседних панелях видны категория, эскалация, расход токенов, HTTP-статус и длительность.
4. Для демонстрации обработки ошибки используйте отдельный запрос и его ID: соответствующие записи появятся в панели **Ошибки и безопасный fallback**. Пустая панель для успешного запроса ожидаема.

Панель **Последние вызовы /triage** не зависит от фильтра Request ID: по ней можно найти недавние ID. Значение `.*` в фильтре показывает события всех запросов за выбранный интервал.

Дашборд отображает только диагностические поля. Тексты обращений и черновики ответов в логи приложения не записываются.
